Wait… Does a Decision Tree Actually Learn Anything?

// A rabbit hole that started with "what are parameters" and ended with a real ML insight nobody tells you about.

by Shivam  ·  K.J. Somaiya CE  ·  April 2026

↓ scroll

It started with a simple question 🤔

"What are the parameters of an ML model?"

Sounds basic, right? Every ML course covers it in Week 1. But push on it a little — ask why, ask what does that actually mean — and things get surprisingly deep.

Let me walk you through exactly how the rabbit hole went.

The boring part first: Parameters vs Hyperparameters

Most people learn this and move on. Here's the clean version:

Parameters Hyperparameters
Who sets them? Model (automatically) You (manually)
When? During training Before training
Dataset dependent? ✅ Yes ❌ No
Example weights w, bias b learning rate, lambda

Best way to picture parameters? Linear Regression.

// Predict house price from size
Price = w × Size + b

// After training on Mumbai data:
Price = 500 × Size + 20000

// w = 500, b = 20000 → these are the parameters
// Train on Nagpur data → different w, different b

The model figured out 500 and 20,000 by minimizing error on your training data. You didn't set them. The data shaped them. That's what "dataset dependent" means.

Scale this up: GPT-4 has ~1.8 trillion parameters. Same idea — just 1.8 trillion ws and bs, all tuned to fit the training data.

Quick check — which of these is a hyperparameter?

Then we got to Decision Trees. And things got interesting.

So what are the parameters of a Decision Tree? The model learns:

DT Parameters (learned from data)
Split feature at each node (e.g. "use Age to split here")
Split threshold at each node (e.g. "Age > 30")
Tree structure — how the branches form
Leaf values — final prediction at each leaf

And the tool it uses to find these? Information Gain (or Gini). You set which criterion to use — that's the hyperparameter. The result of using it (which feature, which threshold) is the parameter.

"IG is like a ruler. The ruler helps you measure. But the measurement you write down — that's the parameter."

Seems clean, right? Parameters ✅. Hyperparameters ✅.

But then came the question that cracked everything open.

🤯 But wait — does a DT actually learn?

Here's the thought: if Information Gain (a hyperparameter) directly determines which feature becomes a parameter, then how much is the model actually learning… and how much is it just mechanically executing a formula you chose?

Is a Decision Tree genuinely learning? Or is it just doing math you told it to do?

+

This is the parametric vs non-parametric distinction — and it's something most ML courses skip entirely.

Linear/Logistic Regression is parametric. It assumes a fixed functional form (a line, a plane), then genuinely optimizes w and b by minimizing a loss function using gradient descent. The model is doing real mathematical reasoning — iteratively adjusting, globally searching for the best values.

Decision Trees are non-parametric. There's no loss function being minimized. No gradient. No global optimization. It's a greedy algorithm — at each node, just pick the locally best split right now using IG/Gini, and move on. It never goes back and reconsiders.

DT "parameters" aren't learned in the same sense — they're stored decisions from a greedy mechanical process.

The key difference
Regression finds the globally optimal w and b by minimizing error across all data simultaneously.

A Decision Tree just makes the best local decision at each node, one at a time, never looking back.

This is why you'll hear ML engineers say "a standalone decision tree is a weak learner." Not just because it overfits — but because its whole learning process is fundamentally local and greedy.

Then why use Decision Trees at all?

Fair question. If DTs don't truly optimize, what's the point?

Hint: it's not computation speed 🤔
+
  • Non-linear decision boundaries — regression draws lines; DTs carve the space in any shape
  • Interpretability — you can literally read the tree and explain every decision. Try that with a neural net.
  • No feature scaling needed — Age=30 and Income=500000 coexist fine
  • Handles mixed data types — categorical and numerical features together
  • Fast inference — traversing a tree is O(depth)

And here's the kicker — the greedy weakness of individual DTs is exactly why ensembles exist.

Random Forest and XGBoost don't just use many trees — they're designed to compensate for the greedy nature of individual trees by aggregating or boosting across many of them.

The limitation of a single DT is the very reason Random Forest works. One greedy tree = weak. A thousand slightly different greedy trees, averaged = surprisingly powerful.

Which statement correctly describes a Decision Tree's "learning"?

The full picture 🗺️

Model Parameters How Learned
Linear Regression w, b Gradient Descent (global optimization)
Logistic Regression w, b Gradient Descent (global optimization)
Decision Tree split feature, threshold, leaf values Greedy IG/Gini (local decisions)
Neural Network w, b per neuron (millions) Backprop + Gradient Descent
🏁 Final Verdict

Parameters are always learned from data. But how they're learned varies wildly. Regression and neural networks genuinely optimize — they find globally good values. Decision Trees store greedy decisions — locally optimal, but never globally reasoned.

This is why "parametric vs non-parametric" is a real axis of model comparison — not just textbook trivia.

Why does any of this matter?

It matters when you're choosing models. When someone asks you "why not just always use a DT?" you now have a real answer — not "it overfits" (everyone says that), but that it lacks a global optimization objective, making it inherently limited as a standalone learner.

It matters in interviews. "What does a Decision Tree actually learn?" is a question that separates people who used sklearn from people who understand what's happening underneath.

And honestly — it matters because questioning the obvious is the actual skill. Most people learn "DT uses IG to split" and move on. Asking wait, but then is it actually learning anything? is how you find real insights.

This whole post came from one conversation where someone refused to accept a surface-level answer. That's the energy.
